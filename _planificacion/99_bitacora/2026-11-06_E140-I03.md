# Bitácora · E140-I03 · Corrección: el Worker no atiende los 404 del sitio

- **Iteración:** E140-I03

- **Agente:** Claude Code · modelo: Claude Opus 5.5

## Resumen
En la preview, con `main` en `wrangler.jsonc`, Cloudflare entregaba al Worker toda URL que no existe en `dist/`, y el Worker respondía `{"ok":false,"error":"Not found"}` en lugar de la página 404 (AT-102). Ahora `src/worker/index.ts` responde 404 JSON solo en `/api/*` y devuelve todo lo demás a los assets con `env.ASSETS.fetch(request)`, con lo que vuelve a aplicar `not_found_handling: "404-page"` (ADR-085). `verify:seo` ejecuta el Worker con un `ASSETS` simulado y comprueba que esas rutas no reciben JSON. No se tocó el archivo ni la bitácora de E140-I02 (ADR-056).

## Bloque para `wrangler.jsonc` (lo aplica Felipe, ADR-033)
Agregar `"binding": "ASSETS"` en `assets`; el resto queda igual. Terminar el archivo con un salto de línea:

```jsonc
// Worker de felipecuevas.dev con assets estáticos (ADR-037) y función de contacto (ADR-084).
// "main" atiende /api/* (run_worker_first); lo que no existe en dist/ vuelve a los assets por
// el binding ASSETS para mostrar la página 404 (ADR-085).
// Sin rutas ni dominio: hasta el cutover (E190-I02) solo responde en workers.dev.
{
  "$schema": "./node_modules/wrangler/config-schema.json",
  "name": "felipecuevas-dev",
  "main": "./src/worker/index.ts",
  "compatibility_date": "2026-10-23",
  "assets": {
    "directory": "./dist",
    "binding": "ASSETS",
    "not_found_handling": "404-page",
    "run_worker_first": ["/api/*"],
  },
  "workers_dev": true,
  "preview_urls": false,
}
```

El código y el bloque se publican juntos: sin el binding, `env.ASSETS` no existe y las rutas inexistentes darían 500.
