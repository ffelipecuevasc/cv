Notas del bloque 3:
- Sintaxis de las reglas MCP verificada en la documentación oficial de Claude Code (`code.claude.com/docs/en/permissions`, leída el 24-11-2026): `mcp__<servidor>__*` cubre todo el servidor, `mcp__<servidor>__<herramienta>` una herramienta, y la precedencia es `deny`, luego `ask`, luego `allow`. La página no muestra su fecha de actualización.
- `enabledMcpjsonServers` existe según el índice de la referencia de ajustes; **no confirmé** el formato exacto de su valor (aquí, una lista de nombres) ni los nombres reales de las herramientas de Playwright MCP (`browser_evaluate`, etc.): la fase 2 los verifica con el servidor real y, si difieren, entrega un bloque corregido. Hasta entonces, las reglas `ask` con un nombre inexistente no hacen daño, pero tampoco protegen.
- La documentación dice que, en una carpeta no confiable, las claves `enableAllProjectMcpServers` y `enabledMcpjsonServers` del `.claude/settings.json` del proyecto se ignoran: si Claude Code no pide aprobar el servidor ni lo marca aprobado, hay que aprobarlo una vez de forma interactiva.
- `.mcp.json` no está en la lista `deny` de edición. Si quieres que el agente no pueda cambiarlo, agrega `"Edit(/.mcp.json)"` a `deny` después de la fase 2.
