# Bitácora · E10-I07 · i18n base: enrutamiento /es/ y /en/

- **Iteración:** E10-I07
- **Fecha:** 2026-10-28
- **Agente:** Claude Code · modelo: Claude Opus 5.5 (`claude-opus-5-5`)
- **Rama:** `migracion-astro` (no es `main`)
- **Estado final:** Terminada

## Resumen
Se configuró el i18n nativo de Astro 7.4.2 con `es` (`es-CL`) y `en` (`en-US`), ambos con prefijo en la URL y sin fallback. Se crearon las páginas mínimas `/es/` y `/en/` con su `lang` correcto y se eliminó la página de prueba de E10-I03 con la clase temporal `text-[13.37px]`. La raíz `/` redirige de forma provisoria a `/es/` con la opción `redirects` de Astro (meta refresh), porque `redirectToDefaultLocale` exige una página índice en la raíz. La 301 definitiva queda para E180-I03 (ADR-019, AT-046).

## Convención de i18n
- **Configuración** (`astro.config.mjs`, ADR-034):
  ```js
  i18n: {
    locales: [
      { path: 'es', codes: ['es-CL', 'es'] },
      { path: 'en', codes: ['en-US', 'en'] },
    ],
    defaultLocale: 'es',
    routing: { prefixDefaultLocale: true },
  },
  redirects: { '/': '/es/' },
  ```
- **Carpetas:** toda página vive en `src/pages/es/` o `src/pages/en/`, con el mismo árbol en ambos idiomas. No se crean páginas en la raíz de `src/pages/`.
- **Slugs:** en `/es/` se conservan en español (`recursos.astro`) y en `/en/` se traducen (`resources.astro`), según ADR-020 y ADR-025. El mapa de rutas equivalentes se cierra en E30-I02.
- **Idioma del documento:** `<html lang={Astro.currentLocale}>`. Con locales en forma de objeto, `Astro.currentLocale` entrega el primer código: `es-CL` o `en-US`. Los textos de interfaz llegarán desde el diccionario (E30-I02).
- **Sin fallback:** si falta una página en un idioma, responde 404. La paridad la exige ADR-001 y la verificará E170-I04.
- **Raíz `/`:** `dist/index.html` es una redirección provisoria con meta refresh, `noindex` y canónica a `/es/`. No es contenido.
- **Sin SSR:** no hay middleware ni adaptador; todo se resuelve en el build (ADR-018).
